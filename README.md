# O&M handover pack — gap report

Reads a folder of building-services handover documents and reports what is
**missing**, which is the part nobody can do by eye.

Assembling an O&M pack is clerical work. The expensive moment comes eighteen
months later, when someone needs the commissioning certificate for a unit that
never had one and the installing contractor has moved on. This finds that on
the day the pack is issued instead.

## Run it

```bash
python3 -m venv .venv && .venv/bin/pip install -r requirements-dev.txt
.venv/bin/python samples/generate.py              # build the sample pack
.venv/bin/python -m handover.cli samples/pack     # the report
.venv/bin/python -m handover.cli samples/pack --json report.json
.venv/bin/python -m pytest tests/ -q
```

## The three problems that make this non-trivial

**One asset, written five ways.** `AHU-01`, `AHU 01`, `AHU01`, `ahu-1` are the
same unit, and four subcontractors will use four of those spellings. Without
normalisation the tool reports a missing certificate that is sitting in the
folder — which destroys trust in every other line of the report. This is the
single most important rule in the codebase and it has its own tests.

**A blank that looks filled in.** `Serial No: TBC` is a gap, not a serial
number. Recording it as a value hides the gap behind something that looks
complete. The same placeholder rule is shared by the register parser and the
document parser, because having two copies is how they drift apart.

**Completeness is not one checklist.** Electrical plant needs an installation
certificate; mechanical plant needs commissioning results; public health needs
both. Requirements are keyed by discipline, and discipline is inferred from the
tag prefix — and marked `inferred`, never `certain`.

## How it reads a document

Text layer first; OCR only when there isn't one. OCRing a clean PDF is a way to
introduce errors into text that was already perfect.

A file nothing can be read from is **listed as unreadable**, never silently
dropped, and cross-referenced against the gaps — because the sharpest failure
this tool could have is announcing that an asset has no commissioning
certificate while that certificate sits in the folder as a photograph:

```
UNREADABLE — may be hiding the gaps above
────────────────────────────────────────────────────────────────────────
  36-scan-fcu-03.pdf
      ⚠ filename suggests FCU-03, which is reported
        above as missing: commissioning certificate, warranty
        Read this file before chasing anyone.
  37-scan-cws-01.pdf
      · filename suggests CWS-01, which is not in the register at all
```

The filename is a hint, not a fact, and is reported as one. The two sample
scans are deliberately different cases: one hides a gap the report is already
complaining about, the other is plant nobody recorded anywhere.

OCR is an optional import. The pipeline runs without it, and says so.

## Confidence, and why nothing is silently upgraded

Every extracted value carries how it got there:

| | |
|---|---|
| `certain` | parsed from structured text by a rule |
| `inferred` | derived, e.g. discipline from a tag prefix |
| `unverified` | proposed but failed or skipped its checks |

A wrong value stated confidently is worse than an admitted gap. The whole point
of the report is to be trusted about absence, so nothing promotes its own
trust level.

**On the language model.** Rules extract first; a model only sees the residue
they could not parse, and whatever it returns passes the *same* schema
validation as rule output, entering as `unverified` until it does. That keeps
the pipeline deterministic, free to run in CI, and honest — the interesting
engineering is the validation boundary, not the prompt.

## The sample pack

Generated by `samples/generate.py`, entirely invented — no client material, no
real projects. It is generated rather than committed so the faults in it are
defined in code and the end-to-end test can assert against them exactly.

Seeded faults: assets with no certificates at all, a certificate for plant that
was never in the register, `TBC` serial numbers, the same tag written four ways,
and two image-only scans — one of which contains a certificate the report
otherwise declares missing.

## CI

Every push generates the pack, runs 26 tests, and prints the gap report into
the build log. The run is the evidence.

## Not a compliance tool

It reports what is absent from a pile of documents. It does not certify that
anything present is correct, valid or signed by someone competent.
